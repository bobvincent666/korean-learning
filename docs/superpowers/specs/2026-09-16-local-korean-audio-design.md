# 本地预生成韩语音频设计

## 目标与范围

把现有四组拼读表、单词与句子的小喇叭改为优先播放随网站发布的音频。访客无需安装 `ko-KR` 系统语音，也无需在播放时访问语音合成服务。保留正常、慢速和重复上一段功能。视频功能不变。

当前 `data.js` 与 `render.js` 共引用 149 段不重复的韩语朗读文本（包括元音示范音节、辅音示范音节、拼读格、单词、句子）。生成脚本每次从现有数据重新枚举、去重，不手写第二份教材清单。

## 声源选择

采用 [Ppaso-TTS v1](https://huggingface.co/akamotaco/ppaso-tts-v1) 的韩语单声线 ONNX CPU 模型。其模型卡标注 Apache-2.0，可用于商业场景；同时明确提醒音色略机械、少见读音可能不准。仅将合成后的音频放入网站，模型权重与 Python 运行环境不随网站部署。在仓库记录模型来源、固定的上游版本、许可与生成日期。

不采用 Piper 的 `ko_KR-kss-medium`：其[模型卡](https://huggingface.co/rhasspy/piper-voices/blob/main/ko/ko_KR/kss/medium/MODEL_CARD)标注训练数据为 CC BY-NC-SA 4.0，不适合作为可能公开或企业使用的默认声源。也不从 Windows/浏览器的播放输出录音，因为声源和再分发条件不明确。

## 数据流与组件

1. `tools/` 中的 Node 清单导出脚本从 `data.js` 枚举所有按钮的韩语文本，做 Unicode NFC 规范化与去重，以 UTF-8 文本散列生成稳定文件名。Python 生成脚本读取这份清单。
2. Python 脚本调用固定上游提交的 Ppaso-TTS 模型合成 WAV，再用 FFmpeg 转成单声道 MP3。把文件存入 `audio/`，并生成供前端读取的文本到文件路径清单。默认跳过已有音频，只有显式要求时才覆盖；失败的条目不得以空白或静音文件冒充成功。
3. 前端播放层按按钮的 `data-speak` 查清单，使用 `HTMLAudioElement` 播放。慢速使用同一文件的 `playbackRate = 0.78`，重复功能重播上一次文本及速度；切换音频时停止上一段。
4. 音频文件缺失、加载或播放失败时显示明确提示；可尝试现有浏览器韩语语音作为次级回退，但不依赖它完成正常播放，也不回退到中文或英语声线。
5. 静态网站与 `audio/` 一起部署。模型和 Python 依赖仅在制作音频的电脑上需要；无需云端 TTS 密钥或实时合成接口。

## 发音质量控制

先合成覆盖松音、紧音、送气音、复合元音、单词、句子的代表样本，检查文件可解码、非静音、时长合理，并供试听。再批量生成全部条目；对每个文件做解码、时长、响度与清单覆盖检查。自动检查不能证明读音教学准确，发布前仍需韩语熟练者抽听，重点检查孤立音节及连音句子。若模型对某项读错，可用人工审定音频替换该文件，而不改变页面数据；默认跳过已有文件以免下次生成时覆盖人工修正。

## 测试与验收

- 单元测试覆盖文本去重、清单完整性、文件名稳定性，以及播放、慢速、重复和失败提示。
- 集成检查确认所有 `data-speak` 文本都有音频文件，文件可被 FFmpeg 解码且不是零字节。
- 在没有 `ko-KR` 浏览器语音的环境中，随机点击四表、单词和句子的小喇叭，仍可播放；慢速、重复正常。
- 音频生成/压缩在本地完成，网站运行与云端静态发布不需要模型、Python 或语音服务密钥。

## 不在本次范围

不支持用户输入任意新文本实时合成，不替换视频源，不更改四组教材内容或罗马字标注。不承诺机器合成音频达到母语教师录音的教学精度。
